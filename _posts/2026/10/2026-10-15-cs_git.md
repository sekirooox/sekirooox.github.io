# Git 版本控制

## 数据模型

### Blob 与 Tree

Git 将文件和目录的历史建模为一系列快照。在 Git 的对象模型中，文件内容保存为 `blob`，本质是一组字节；目录保存为 `tree`，负责将名称映射到 `blob` 或其他 `tree`，因此可以表达嵌套目录。每个快照都以项目的顶层 `tree` 为入口。

```text
<root> (tree)
|
+- foo (tree)
|  |
|  +- bar.txt (blob, contents = "hello world")
|
+- baz.txt (blob, contents = "git is wonderful")
```

顶层 `tree` 包含目录 `foo` 和文件 `baz.txt`；其中，`foo` 又包含文件 `bar.txt`。

### 快照与提交

Git 使用 `commit` 记录快照。每个提交会保存顶层 `tree`、父提交以及作者等元数据，因此提交历史构成有向无环图（DAG）。

```text
o <-- o <-- o <-- o
            ^
             \
              --- o <-- o
```

子提交在时间上晚于父提交；多个子提交可以指向同一个父提交，从而形成分支。<span style="color:red">已有提交不可变</span>，需要修正历史时，应创建新提交或显式改写引用。

### 对象

`blob`、`tree` 和 `commit` 都属于 Git 对象。Git 根据对象内容计算哈希值，并以该哈希进行寻址。

例如，可以读取一个 `tree` 对象：

```shell
git cat-file -p 698281bc680d1995c5f4caaf3359721a5a58d48d
```

```text
100644 blob 4448adbf7ecd394f42ae135bbeed9676e894af85    baz.txt
040000 tree c68d233a33c5c06e0340e4c224f0afca87c8ce87    foo
```

`tree` 保存其子对象的类型、哈希和名称。继续读取 `baz.txt` 对应的 `blob`，即可得到文件内容：

```shell
git cat-file -p 4448adbf7ecd394f42ae135bbeed9676e894af85
```

```text
git is wonderful
```

> Git 对对象进行内容寻址：类型与内容均相同的对象对应相同标识，目录树通过哈希引用具体内容。

### 引用

直接记忆完整哈希并不方便。Git 因此提供引用（reference，简称 `ref`），用可读名称指向提交。对象通常不可变，而引用可以随着新提交不断更新；分支就是最常见的引用。

> `main`、`dev` 等分支名本质上都是指向某个提交的可移动引用。

#### HEAD

`HEAD` 表示当前检出的提交。通常情况下，`HEAD` 间接指向当前分支，分支再指向最新提交：

```text
HEAD -> main -> commit
```

因此，`HEAD` 用于标识当前工作位置，但它并不等同于提交哈希。

#### Detached HEAD

当直接检出某个提交或标签时，`HEAD` 会直接指向该提交，而不再依附某个本地分支，这种状态称为 `detached HEAD`。此时仍可创建提交，但若要长期保留这些提交，应及时新建分支：

```shell
git switch -c new-branch
```

### 仓库

Git 仓库可以概括为对象与引用的集合。对象保存文件内容、目录结构和提交记录，引用则负责定位并组织不同提交。仓库中的 `.git` 目录还包含配置、暂存区等内部数据。

### 暂存区

使用 `git add` 可以把指定文件的当前内容写入暂存区，例如：

```shell
git add path/to/file
```

暂存区用于选择下一次提交包含哪些改动，使同一工作目录中的修改可以拆分到不同提交中。例如，同时完成两个独立功能时，可以分别暂存并提交；修复缺陷时，也可以通过 `git add -p` 按变更块暂存修复内容，不纳入临时调试语句。

## 工作区、本地仓库与远程仓库

代码通常在工作区、暂存区、本地仓库和远程仓库之间流转：

- 使用 `git add` 将工作区改动加入暂存区；
- 使用 `git commit` 将暂存内容记录到本地仓库；
- 使用 `git push` 将本地提交发送到远程仓库；
- 使用 `git fetch` 或 `git pull` 获取远程更新。

## 提交历史与指针

- 每次提交都会生成新的提交记录，当前分支引用随之向前移动；
- `HEAD` 通常指向当前分支，而当前分支指向最新提交；
- `git reset` 的核心作用是移动当前分支引用，并按模式决定是否同步暂存区与工作区。

## 基本操作

### 将改动加入暂存区

```shell
git add .
```

- `git add .`：暂存当前目录及其子目录中的相关改动；
- `git add path/to/file`：仅暂存指定文件；
- 在 VS Code 的源代码管理面板中，也可以点击文件旁的加号完成暂存。

<figure><img src="/assets/img/posts/cs-git/tui-jian-xi-tong-vscode-zan-cun-gai-dong.png" alt="VS Code暂存" width="368"><figcaption><p>VS Code 暂存文件改动</p></figcaption></figure>

### 提交到本地仓库

```shell
git commit -m "git_test_2"
```

`git commit -m "提交说明"` 会将暂存区内容创建为本地提交。提交说明应简洁概括本次变更；也可以在 VS Code 中填写说明并完成提交。

## 分支管理

分支是指向提交的可移动引用，用于承载不同的开发线。切换分支后，Git 会根据目标提交更新工作区文件；本地分支与远程跟踪分支是不同类型的引用。

<figure><img src="/assets/img/posts/cs-git/tui-jian-xi-tong-github-fen-zhi-lie-biao.png" alt="GitHub分支" width="760"><figcaption><p>GitHub 仓库分支列表</p></figcaption></figure>

### 查看分支

```console
(base) a2023102747@zyserver:/home/shared/ml/hello-github$ git branch
  debug
  dev
  dev1
* master
```

星号表示当前分支。

### 切换分支

```console
(base) a2023102747@zyserver:/home/shared/ml/hello-github$ git checkout debug
Switched to branch 'debug'
```

也可以使用语义更明确的命令：

```shell
git switch debug
```

未提交的改动在不冲突时可能会随切换保留；若改动会被目标分支覆盖，Git 会阻止切换。切换前应先提交、暂存或妥善保存当前工作。

### 创建并切换新分支

```shell
git checkout -b test
```

该命令会基于当前位置创建 `test` 分支并立即切换过去。对应的新命令为：

```shell
git switch -c test
```

### 合并分支

```shell
git merge test
```

- `git merge test` 会将 `test` 分支合并到当前分支；
- 若出现冲突，需要手动选择或整合冲突内容，再完成提交；
- 常见流程是在开发分支达到上线标准后，切换到 `main` 或 `master`，再合并开发分支。

## 回退提交

```shell
git reset [--soft | --mixed | --hard] <commit_id>
```

- `--soft`：移动 `HEAD`，暂存区和工作区保持不变；
- `--mixed`：默认模式，移动 `HEAD` 并重置暂存区，工作区保持不变；
- `--hard`：移动 `HEAD`，同时重置暂存区和工作区，未保存的改动会被丢弃。

执行 `git reset --hard` 前必须确认目标提交和待保留改动。对于已经共享到远程仓库的历史，通常优先使用 `git revert` 创建反向提交，以避免改写公共历史。

## 仓库状态与历史

### 查看当前状态

```console
(base) a2023102747@zyserver:/home/shared/ml/hello-github$ git status
On branch master
nothing to commit, working tree clean
```

`git status` 会显示当前分支、暂存区状态以及工作区中尚未暂存的改动。

### 查看提交历史

```console
(base) a2023102747@zyserver:/home/shared/ml/hello-github$ git log
commit 1e84a2ac1c34c985713b2431e63792f0aaa5bea7 (HEAD -> master, origin/master)
Merge: c9eeff4 5ab26d5
Author: sekirooox <2792801628@qq.com>
Date:   Tue Apr 14 22:33:56 2026 +0800
```

`git log` 用于查看提交哈希、作者、时间和提交说明。若希望快速观察分支结构，可以使用：

```shell
git log --oneline --graph --decorate --all
```
