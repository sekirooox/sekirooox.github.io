# 基本操作
## 提交到贮存区：`git add . `
```cpp
git add . 
```
+ 建议使用 `git add ./`添加所有的文件
+ 使用vscode的界面，先把修改文件加入到**暂存仓库**，然后提交到**本地仓库**即可。 ![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/a511a6f2681e498aa9da47417fb7a222.png){: referrerpolicy="no-referrer" }

## 提交到本地仓库：`git commit -m`

```cpp
git commit -m "git_test_2" 
```
提交的本地仓库
+ `git commit -m "abcdefg"`，可以直接使用vscode界面的消息，支持中文，比较方便

## 分支：`branch`
+ 分支就是同一个工作区文件的不同视角
+ 本质上**仍然存储在本地**，但是**视角(能看到哪些文件)不同**。
![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/c452d5e667454520a750d7e99ae465da.png){: referrerpolicy="no-referrer" }
### 查看分支：`git branch`

```cpp
(base) a2023102747@zyserver:/home/shared/ml/hello-github$ git branch
  debug
  dev
  dev1
* master
```

### 转换分支：`git checkout`
+ `git checkout debug`：转换到debug分支
+ **会继承当前branch的贮存记录！会继承当前branch的贮存记录！会继承当前branch的贮存记录！**

```cpp
(base) a2023102747@zyserver:/home/shared/ml/hello-github$ git checkout debug
Switched to branch 'debug'
```

### 创建新分支：`git checkout -b test`

`git checkout -b test`：**新建一个分支**，然后**返回原始分支**，将**新分支与原分支**进行合并`git merge test`

## 分支合并：`git merge xxx`
+ 默认是当前分支合并目标分支
+ **如果出现冲突，需要手动确定哪一个版本为主**。
![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/e72022c7c8934bf5aa8dae47add36787.png){: referrerpolicy="no-referrer" }
### 应用：开发分支（dev）上的代码达到上线的标准后，要合并到 master 分支
<br><br><br><br>

## 代码回溯：`git reset <commit_id> --hard/soft/mixed`
+ 默认方式：返回到某一次提交，放弃贮存区的文件(也就是提交历史)，**工作目录文件不变**
+ hard：**删除工作目录**和提交历史，完全删除。
